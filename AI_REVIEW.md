# Использование и проверка ИИ в WebLab#3

ИИ помог с разбором OpenAPI v2, реализацией отдельных слоёв и GUI,
подготовкой контрактного сценария и отчёта. Результат проверялся по сохранённому
OpenAPI, существующему стилю проекта и на PostgreSQL.

## Исправления после ревью

- Первые варианты смешивали доменную сущность и интерфейс репозитория в одном
  файле и называли основные файлы `*_v2`. Код переразложен: основной путь
  имеет обычные имена, совместимость v1 — префикс `legacy_*`, доменные
  интерфейсы, модели БД и SQL лежат в принятых проектом местах.
- У пользовательских маршрутов была ошибочная проверка роли администратора.
  Маршруты v2 и v1 разделены по роли; обычный пользователь теперь управляет
  собственными данными, а администратор — каталогом лекарств.
- Проверка контракта обнаружила неверный статус для неадминистратора:
  `401` изменён на `403`. PostgreSQL проверен повторно.
- Для частичного изменения лекарства сохранены ID правил дозировки, если
  массив дозировок не передан. Это проверено тестом и запросом к PostgreSQL.
- Конфликт одинаковых позиций защищён уникальным индексом PostgreSQL,
  а доступ к чужим ресурсам не раскрывает их наличие.

## Проверяемость

`scripts/check_v2.py` выполняет сценарии для всех групп из 26 операций.
`go test ./...`, `go vet ./...` и `npm --prefix gui run build` проходят.
Для проверки чувствительности контрактного теста поле ответа аптечки временно
переименовывалось; тест упал и прошёл после возврата правильного имени.
Тестирование выполнялось на временных БД, без очистки исходных данных проекта.
