# Использование и проверка ИИ в WebLab#3

ИИ помог с разбором OpenAPI v2, реализацией отдельных слоёв и GUI,
подготовкой контрактного сценария и отчёта. Результат проверялся по сохранённому
OpenAPI, существующему стилю проекта и на PostgreSQL.

## Исправления после ревью

- Первые варианты смешивали доменную сущность и интерфейс репозитория в одном
  файле и называли основные файлы `*_v2`. Код переразложен: основной путь
  имеет обычные имена, совместимость v1 — префикс `legacy_*`, доменные
  интерфейсы, модели БД и SQL лежат в принятых проектом местах.
- У пользовательских маршрутов была ошибочная проверка роли администратора.
  Маршруты v2 и v1 разделены по роли; обычный пользователь теперь управляет
  собственными данными, а администратор — каталогом лекарств.
- Проверка контракта обнаружила неверный статус для неадминистратора:
  `401` изменён на `403`. PostgreSQL проверен повторно.
- Для частичного изменения лекарства сохранены ID правил дозировки, если
  массив дозировок не передан. Это проверено тестом и запросом к PostgreSQL.
- Конфликт одинаковых позиций защищён уникальным индексом PostgreSQL,
  а доступ к чужим ресурсам не раскрывает их наличие.

## Проверяемость

`scripts/check_v2.py` выполняет сценарии для всех групп из 26 операций.
`go test ./...`, `go vet ./...` и `npm --prefix gui run build` проходят.
Для проверки чувствительности контрактного теста поле ответа аптечки временно
переименовывалось; тест упал и прошёл после возврата правильного имени.
Тестирование выполнялось на временных БД, без очистки исходных данных проекта.

# Использование и проверка ИИ в WebLab №4

**Инструмент:** Codex (GPT-6). **Задача:** настроить воспроизводимый стенд
WebLab №4 поверх существующих API v1/v2 и GUI. Реализация выполнялась по шагам
с отдельной проверкой каждого результата.

**Результат:** [инструкция запуска](README.md#запуск-стенда-weblab-4),
[таблица маршрутов](docs/web/lab4-routing.md),
[конфигурация Compose](docker-compose.yaml) и
[HTTP-проверки](scripts/check_web4.py). Из бонусов реализовано отображение
README как HTML на `/documentation`.

**Решения после проверки**

- При проверке прокси Nginx возвращал `502 no live upstreams`. Вместо
  динамического поиска Go-сервиса при старте Nginx использует имя сервиса
  Compose. Compose запускает Go перед Nginx и перезапускает Nginx при
  обновлении Go. Повторные запросы к v1 и v2 прошли.
- Swagger v1 получил базовый путь `/api/v1` при запуске Go. Это позволяет
  выполнять операции из Swagger через версионные маршруты Nginx и сохраняет
  `/admin/` за интерфейсом PostgreSQL.
- По уточнению пользователя логин и пароль для Nginx вынесены в
  `ADMIN_USER` и `ADMIN_PASSWORD` в локальном `.env`. Вход в PostgreSQL
  использует отдельные учётные данные. Проверены пустой пароль, успешный вход
  и отказ по старым данным после смены логина и пароля.

**Итоговая проверка**

| Сценарий | Наблюдение |
| --- | --- |
| Смена порта Go с `8080` на `8081` | До и после изменения прошла 61 HTTP-проверка через `127.0.0.1:8088`. Контейнер Go получил `SERVER_PORT=8081`, а загруженная конфигурация Nginx указывает на `app:8081`. `8081` зафиксирован в Compose и шаблоне окружения. |
| Запуск из чистой копии | Стенд собран через Compose на `127.0.0.1:18114` из файлов проекта и нового `.env` по шаблону. PostgreSQL создал схему в отдельном пустом томе. Сборка с последовательным запуском прошла после обрывов соединения с Docker Hub. |
| Интерфейс и Adminer | В Firefox прошли регистрация, повторный вход и создание аптечки. После обновления сессия и аптечка сохранились. Через Adminer выполнен вход в тестовую БД и открыты таблицы `users` и `cabinets`. |
| Отказ Go и PostgreSQL | При остановке каждого компонента `/health`, `/status` и `/management` вернули `200`, а `/ready` вернул `503`. При остановленном Go `make check-web4` завершился с ненулевым кодом. После восстановления прошло 61 из 61 HTTP-проверки. |
| Сборка и статические проверки | Прошли `docker compose config --quiet`, `nginx -t`, `go test ./...`, `go vet ./...` и сборка GUI в Docker. |

Отказы проверялись только на отдельном стенде. Итоговый внешний адрес,
таблица маршрутов и команда `make check-web4` служат основой для WebLab №5 и №8.
