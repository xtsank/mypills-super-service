# WebLab#3 — реализация API v2

## Результат

Основной контракт — [`docs/openapi/v2.yaml`](../openapi/v2.yaml): 26 операций
регистрации, сессии, профиля, справочников, каталога лекарств, аптечек и их
позиций, рекомендаций и списка пополнения. Обработчики зарегистрированы под
`/api/v2`, а Swagger UI по `/swagger/` открывает именно сохранённый контракт.
Старые обработчики вынесены в `legacy_*` и доступны через `/api/v1` и прежние
корневые маршруты. Их Swagger UI доступен по `/swagger-v1/`.

Код v2 следует существующим слоям проекта: `domain` содержит сущности и
интерфейсы репозиториев в отдельных файлах, `service` — сценарии, `transport`
разделяет обработчики и DTO запросов/ответов, реализация PostgreSQL разделяет
`entity`, `queries` и `repository`. Вход и права проверяются
на HTTP границе, а доступ к аптечкам, позициям и списку пополнения проверяется
по владельцу.

GUI переведён на v2 и сохраняет MVVM. Он покрывает вход, профиль, аптечки,
позиции, рекомендации, пополнение и работу администратора с каталогом.

## Хранилище

PostgreSQL — единственное хранилище. Схема содержит аптечки, привязку позиций,
минимальный остаток и список пополнения. Прежние позиции без аптечки
помещаются в домашнюю аптечку при чтении и обновлении, сохраняя свои ID.
При запуске на прежней базе из таблицы пользователей удаляются устаревшие
поля настроек доставки сообщений.

## Проверка

Проверено 26 маршрутов v2 на временном экземпляре PostgreSQL 16 скриптом
`scripts/check_v2.py`. Он проверяет успешные ответы,
валидацию, права администратора и владельца, конфликты, частичный `PATCH`,
заголовок `Location` для `201`, пустое тело `204` и доступность v1. Для запуска
нужен отдельный тестовый backend, администратор с указанными учётными данными
и справочники с ID, указанными в начале скрипта. Скрипт создаёт тестовые
учётные записи и удаляет созданные лекарство, аптечку, позицию и пополнение.

```bash
python3 scripts/check_v2.py --base http://127.0.0.1:8080 \
  --admin-login <тестовый-администратор> --admin-password <пароль>
go test ./...
go vet ./...
npm --prefix gui run build
```

Все четыре проверки завершились успешно. Контрактный тест ответа отдельно
проверялся с намеренным изменением JSON поля аптечки с `name` на `label`:
тест упал, после восстановления `name` прошёл. GUI был открыт в браузере:
проверены экран входа и основной экран аптечки после авторизации.

## Границы проверки

Контрактный smoke сценарий проверяет схему и поведение на характерных данных,
но не заменяет нагрузочный тест требований по задержке. Медицинские рекомендации демонстрируют правила,
заданные учебной предметной областью; они не предназначены для клинического
применения.
