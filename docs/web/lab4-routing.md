# WebLab №4 — таблица маршрутов MyPills

Это схема маршрутов WebLab №4. Страница `/management` содержит ссылки на интерфейс, API, документацию и служебные маршруты стенда.

Внешняя точка входа — `http://127.0.0.1:8088`. Nginx публикуется только на `127.0.0.1` и направляет запросы API в `app:8081`. Внутренний порт задаёт `APP_PORT`, внешний — `WEB_PORT`. Backend, GUI, Adminer и PostgreSQL доступны по внутренней сети Compose. «Без входа» в таблице означает доступ с этого компьютера без дополнительной авторизации.

| Внешний путь | Целевой компонент | Префикс и обработка пути | Ограничения доступа |
| --- | --- | --- | --- |
| `/api/v2/*` | Go/Gin, основной REST API | Сохранить `/api/v2/`, остаток пути и параметры запроса. Неизвестный путь обрабатывает backend. | Передать заголовок `Authorization`. Публичные операции доступны без токена; остальные требуют JWT и прав по контракту. |
| `/api/v1/*` | Go/Gin, совместимый REST API | Сохранить `/api/v1/`, остаток пути и параметры запроса. | Действующие проверки JWT и роли в backend. |
| `/api/v1/docs` | Nginx | Перенаправить на `/api/v1/docs/`. | Без входа. |
| `/api/v1/docs/` и ресурсы под ним | Go/Gin, Swagger UI v1 | Для страницы запросить `/swagger-v1/index.html`. Для ресурсов заменить `/api/v1/docs/` на `/swagger-v1/`, сохранив имя ресурса. | UI доступен без входа. Запросы из него подчиняются правилам API. |

| `/api/spec/v2.yaml` | Go/Gin, OpenAPI v2 | Передать путь как есть: этот адрес использует Swagger UI. | Без входа. |
| `/swagger`, `/swagger/…`, `/swagger-v1`, `/swagger-v1/…` | Go/Gin, прежние адреса Swagger UI | Передать пути как есть. | UI доступен без входа; запросы к API подчиняются правилам API. |
| `/legacy` | Nginx | Перенаправить на `/legacy/`. | Без входа. |

## Вход в Adminer

1. Задай `ADMIN_USER` и `ADMIN_PASSWORD` в локальном `.env`. По умолчанию логин — `webadmin`. Compose передаёт пароль только в Nginx как секрет. При запуске контейнера Nginx создаёт внутренний файл с хешем.
2. На новом стенде запусти `docker compose up -d --build`. После смены логина или пароля пересоздай контейнер командой `docker compose up -d --no-deps --force-recreate nginx`, чтобы Compose загрузил новые значения.
3. Открой `http://127.0.0.1:8088/admin/` и введи `ADMIN_USER` и `ADMIN_PASSWORD`. Затем в Adminer выбери PostgreSQL, укажи сервер `db`, а имя пользователя, пароль и имя базы возьми из `DB_USER`, `DB_PASSWORD` и `DB_NAME` в локальном `.env`.

При пустом `ADMIN_PASSWORD` вход в админку закрыт. Админка доступна через локальный порт Nginx.

## Как проверить схему маршрутов

Запусти стенд и выполни из корня проекта `make check-web4`. Нужен Python 3.
Команда отправляет GET-запросы, сверяет статусы и содержимое ответов и
завершается с ненулевым кодом при первой ошибке. Учётные данные не нужны.

Для отдельного стенда укажи его адрес, например
`make check-web4 WEB4_BASE_URL=http://127.0.0.1:18088`. Остановку сервисов для
проверки отказов выполняй только на отдельном стенде. На работающем стенде
команда проверяет, что `/health` и `/ready` отвечают `200`.

1. Сверить таблицу с пунктами 2–10 WebLab №4 (стр. 9 методички). Точка входа и внутренние сервисы покрывают требования к web-серверу и запуску стенда (пункты 1 и 11).
2. Сверить существующие целевые пути с [регистрацией маршрутов Gin](../../src/cmd/app/app.go) и [контрактом OpenAPI](../openapi/v2.yaml). В контракте пути уже содержат `/api/v2`, поэтому этот префикс сохраняется при проксировании.
3. Проверить пересечения. `/api/v2/docs` обрабатывается точным правилом, а `/api/v2/docs/…` — более узким префиксом Swagger, отдельно от `/api/v2/…`. Например, `/api/v2/docs/swagger-ui.css` уходит на `/swagger/swagger-ui.css`, а `/api/v2/reference` остаётся `/api/v2/reference`. Стартовая страница отдаётся только на `/` и `/reserved/`.
4. Сопоставить `/admin/…` и `/api/v1/admin/…`: первый путь открывает админку БД через Basic Auth, второй остаётся API с проверкой JWT и роли. В Swagger UI v1 операции отправляются с префиксом `/api/v1`, заданным при запуске Go-сервера.
