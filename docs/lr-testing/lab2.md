# ЛР №2: тестовый стенд и проверка

## Что запускается

`docker-compose.test.yaml` поднимает приложение и отдельный PostgreSQL 16. При создании тома PostgreSQL сначала выполняется `src/internal/infra/postgres/init/init.sql`, затем один из файлов в `tests/fixtures/`: `integration_seed.sql` или `e2e_seed.sql`. `Dockerfile.test` собирает отдельный контейнер с Go и зависимостями тестов. `scripts/test-ci-docker.sh` запускает его с доступом к Docker socket, поэтому тестовый контейнер может управлять Compose-стендом. `scripts/test-stand.sh` создаёт стенд, ждёт готовности, пересоздаёт том перед прогоном и восстанавливает исходное состояние после прогона, в том числе при ошибке или прерывании.

Из корня проекта:

```bash
make test              # unit → integration → E2E, затем отчёт Allure
make test-unit         # только unit
make test-integration  # три integration-теста с PostgreSQL
make test-e2e          # один HTTP E2E-тест с PostgreSQL
make allure-open       # открыть локальный отчёт
```

Integration-тесты проверяют запись и чтение аптечки через репозиторий, действие сервиса с сохранением результата и отказ в изменении чужой аптечки. E2E-тест проходит через HTTP: пользователь создаёт аптечку, кладёт в неё два лекарства и получает рекомендацию только безопасного для водителя препарата. Действия E2E также повторяются через `curl` и записываются в Wireshark: [инструкция](lab2-wireshark.md), [захват](e2e-http.pcapng).

## CI и отчёт

Workflow `.github/workflows/lab2-tests.yml` запускается при push в `lab2-testing`, pull request в `main` или вручную. Граф зависимостей: **Unit tests → Integration tests → E2E test → Allure report**. При ошибке следующая тестовая job не запускается; завершающая job всё равно создаёт отчёт и отмечает неисполненные тесты как `skipped` в Allure.

На странице запуска Actions доступны скачиваемый `allure-report.html` и артефакт `allure-history` для следующего запуска. Отчёт каждого запуска остаётся привязанным к этому запуску. История для трендов берётся из артефакта предыдущего запуска той же ветки; начальный снимок локальной истории находится в `.github/allure-history-bootstrap/`.

Тренд длительности показывает сумму времени выполнения отдельных тестов, записанную Allure. После генерации `scripts/fix-allure-duration-trend.mjs` заменяет стандартную длительность от первого теста до последнего, в которую входят паузы на подготовку Docker-стендов. Тот же пересчёт применяется к старым точкам истории и к скачиваемому однофайловому HTML. Времена самих тестов и Timeline не меняются.

## Проверки устойчивости

Проверено локально 4 ноября 2026 года:

| Проверка | Результат |
| --- | --- |
| Два последовательных `make test-integration-run` с одинаковыми `TEST_RUN_ID=lab2-repeat` и `TEST_APP_PORT=18084` | Оба раза прошли все три integration-теста. После каждого прогона удалялись контейнеры и том PostgreSQL. |
| Два одновременно работающих стенда `lab2-parallel-a:18085` и `lab2-parallel-b:18086` | На обоих одновременно прошли три integration-теста. После добавления одной строки в БД A там было три аптечки, в БД B осталось две. |
| Принудительный `SIGTERM` после `INSERT` в стенде `lab2-failure:18087` | До прерывания в таблице `Cabinets` было две строки. Команда вернула код 143; стенд пересоздал том. После прерывания в таблице осталась одна исходная строка, добавленная исчезла. |

Для одновременных локальных запусков в **двух отдельных копиях репозитория** задавайте разные `TEST_RUN_ID` и `TEST_APP_PORT`; тогда Compose-проекты, тома и порты не пересекаются:

```bash
# Первая копия проекта
TEST_RUN_ID=alice TEST_APP_PORT=18085 make test-integration

# Вторая копия проекта, запущенная одновременно
TEST_RUN_ID=bob TEST_APP_PORT=18086 make test-integration
```

Пример проверки восстановления после прерывания (код 143 ожидается):

```bash
export TEST_RUN_ID=lab2-failure TEST_APP_PORT=18087
sql="INSERT INTO Cabinets (id, user_id, name) VALUES ('00000000-0000-4000-8000-000000000099', '00000000-0000-4000-8000-000000000001', 'Interrupted run')"
./scripts/test-stand.sh run sh -c '
  ./scripts/test-stand.sh db -c "$1"
  kill -TERM "$$"
' _ "$sql"
./scripts/test-stand.sh db -At -c 'SELECT COUNT(*) FROM Cabinets'
./scripts/test-stand.sh down
```

Приложение выдаёт JWT и не хранит активные пользовательские сессии в отдельном хранилище. Очередь сообщений в проекте не используется. Тестовое окружение полностью удаляется вместе с БД после обычных `make`-прогонов.
