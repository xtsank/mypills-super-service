# ЛР №2: запись HTTP-сценария в Wireshark

Для задания повторяется тот же сценарий, что и в `TestE2E_DriverGetsSafeMedicineFromCabinet`: водитель регистрируется, создаёт аптечку, добавляет безопасное и небезопасное для водителя лекарства, затем запрашивает рекомендацию. Запросы выполняет `curl`, а `dumpcap` из комплекта Wireshark записывает пакеты.

Из корня проекта:

```bash
./scripts/capture-e2e-traffic.sh
wireshark docs/lr-testing/e2e-http.pcapng
```

Скрипт поднимает отдельный Compose-стенд с PostgreSQL и приложением, используя `tests/fixtures/e2e_seed.sql`, ждёт его готовности, захватывает локальный TCP-порт `18081`, проверяет ответы всех пяти запросов и удаляет стенд вместе с тестовой БД. При сбое или прерывании стенд также удаляется. Результат сохраняется в `docs/lr-testing/e2e-http.pcapng` (повторный запуск заменяет файл). Нужны Docker, `curl`, `jq` и право на захват пакетов через Wireshark `dumpcap`.

В Wireshark откройте файл и установите фильтр отображения:

```text
http && tcp.port == 18081
```

В захвате должны быть четыре `POST` (`/api/v2/users`, `/api/v2/cabinets`, дважды `/api/v2/cabinets/{id}/items`) и один `GET /api/v2/recommendations`. Ответы: четыре `201 Created` и один `200 OK`. Чтобы увидеть отдельный обмен целиком, выберите пакет и откройте **Follow → TCP Stream**.

В файле записаны только данные временного тестового стенда. Поскольку HTTP не шифруется, Wireshark показывает тестовый пароль и токен из этого сценария; для реальных учётных записей такой способ записи не подходит.

Если порт `18081` занят, выберите другой перед запуском:

```bash
TEST_APP_PORT=18082 ./scripts/capture-e2e-traffic.sh
```

Тогда замените порт и в фильтре Wireshark. Если стенд уже поднят отдельно с E2E-данными, можно повторить только HTTP-действия командой `E2E_BASE_URL=http://127.0.0.1:18081 ./scripts/replay-e2e-http.sh`.
